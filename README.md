# 高校学科竞赛管理系统

Flask + SQLite 实现的教学竞赛管理平台，对应开题报告《基于 Flask 框架的高校学科竞赛管理系统的设计与实现》。

三类角色：**学生**报名竞赛、**教师**审核与打分、**管理员**发布竞赛与公示获奖。

---

## 1. 五分钟跑起来

在 PowerShell 里依次执行（`python` 已经在你的 PATH 里）：

```powershell
cd "D:\Data management system\contest_system"
pip install flask
python app.py
```

看到 `Running on http://127.0.0.1:5000` 就打开浏览器访问这个地址。

## 2. 演示脚本（答辩和面试都用这 6 步）

1. `admin` 登录 → 发布竞赛 → 填表提交 → 列表里出现新竞赛
2. 退出，用 `2023005` 登录 → 进竞赛详情 → 点「立即报名」→ 状态变「待审核」
3. 退出，用 `teacher1` 登录 → 待办 → 通过审核 → 给这位学生打分 88
4. 退出，用 `admin` 登录 → 获奖公示 → 给这位学生评「一等奖」
5. 退出，用 `teacher1` 登录 → 待办 → 「已打分」里能看到这条，但提示**已公示不能改**
6. 回到 `admin` 撤销奖项 → 教师再改分/撤销成绩 → 这条报名回到「待打分」

第 5、6 步最能体现设计：**成绩和获奖是关联的，公示后数据要冻结**。

每一步都有数据变化，**这就是你答辩时最该展示的东西**。

**为什么分 app.py 和 db.py？** 和你之前 Java 项目里的 Controller / Mapper 是一个道理：路由只管接请求，SQL 集中一处，改数据库只动一个文件。

## 4. 数据库设计（6 张表）

```
sys_user        用户（id, 账号, 密码哈希, 姓名, 角色, 学院）
competition     竞赛（id, 名称, 级别, 类别, 主办, 报名起止, 比赛日期, 状态）
registration    报名（id, 竞赛id, 学生id, 状态, 驳回原因）
score           成绩（id, 报名id, 评委id, 分数, 评语）
award           获奖（id, 报名id, 奖项等级）
notice          公告（id, 标题, 内容, 发布人）
```

两个关键约束（答辩最容易被问）：

- `registration` 上 `UNIQUE (competition_id, student_id)`：**同一个人不能重复报同一竞赛**。靠数据库约束保证，不靠代码里「先查再插」——两个人同时点报名也不会产生两条记录。
- `score` 上 `registration_id UNIQUE`：一个报名只有一条成绩，重复打分是覆盖，不是新增。

状态说明：
- 竞赛：1 报名中 / 2 报名截止 / 3 评审中 / 4 已公示
- 报名：0 待审核 / 1 通过 / 2 驳回
- 用户：0 学生 / 1 教师 / 2 管理员

## 5. 为什么用 SQLite，MySQL 什么时候上

SQLite 是 Python 自带的，**不用装任何东西**，一个 `.db` 文件就是整个库，备份就是复制文件。

你现在不需要 MySQL。等要换的时候，只需要改 `db.py` 里的两处：

1. `sqlite3.connect(...)` 换成 PyMySQL 或 SQLAlchemy 的连接；
2. `?` 占位符换成 `%s`。

`schema.sql` 里的建表语句基本可以直接用（`INTEGER PRIMARY KEY AUTOINCREMENT` 换成 `BIGINT AUTO_INCREMENT PRIMARY KEY`）。

**论文/答辩怎么说**：「开发阶段用 SQLite 降低部署成本，SQL 全部采用标准写法，数据层独立封装，后续可平滑迁移到 MySQL。」这是实话，也说得过去。

## 6. 答辩和面试会问的 11 个问题

**Q1：为什么用 Flask 不用 Django？**
Flask 轻量、按需组装，这个系统功能不复杂，用 Flask 够用且代码量少；Django 自带 ORM、Admin、认证，适合更大更标准的项目，但学习成本和目录约束更重。

**Q2：权限怎么控制的？**
三种角色存在 `sys_user.role`。登录后把 `uid` 和 `role` 写进 session，每次请求由 `login_required` 装饰器检查角色，不符合直接 403。**不是靠前端隐藏按钮**——按钮藏了，直接敲 URL 也进不去。

**Q3：怎么防止重复报名？**
数据库唯一约束 `(competition_id, student_id)`，插入冲突时捕获 `IntegrityError` 并提示「你已经报过这个竞赛了」。不用「先查询再插入」，因为并发下两个请求会同时查到空。

**Q4：密码怎么存的？**
用 `werkzeug.security.generate_password_hash` 存加盐哈希，登录时用 `check_password_hash` 比对。库里没有明文，即使库泄露也拿不到原密码。

**Q5：为什么报名单独一张表，不在学生表里加个字段？**
一个学生可以报多个竞赛，是一对多关系，必须单独建表；同时报名表要记录审核状态和驳回原因，这些字段属于「报名」而不是「学生」。

**Q6：成绩表为什么 `registration_id` 唯一？**
一个报名只对应一条成绩，重复打分应该是覆盖。用唯一键 + `ON CONFLICT DO UPDATE`（upsert）实现，不用先查再判断。

**Q7：统计怎么做的？**
SQL 里 `GROUP BY` 学院 / 奖项 / 状态聚合，后端把结果转 JSON 传给页面，前端用 ECharts 渲染柱状图和饼图。

**Q8：两个人同时报名会不会出问题？**
不会。真正兜底的是唯一索引——数据库层面保证只有一条插入成功，另一个收到冲突提示。这比在代码里判断可靠。

**Q9：这个系统的瓶颈在哪？**
SQLite 单文件写锁，只适合小数据量（几百到几千条）；没做缓存；每次请求新建连接。真要上量，换 MySQL、加连接池、热点数据进 Redis。

**Q10：开发中遇到的最大问题？**
（诚实版，按你自己的经历改）最开始只在页面上用 `{% if %}` 藏了按钮，以为就控制了权限，结果直接在地址栏敲 `/stats` 还是能进。后来把权限收到后端的装饰器里，前端只负责显示。

**Q11：成绩打错了怎么改？公示之后还能改吗？**
教师端「已打分」列表里可以改分，也可以撤销（撤销后这条报名回到「待打分」）。但如果这条成绩已经公示获奖，改分和撤销都会被拒绝——因为会出现「一等奖 + 60 分」这种自相矛盾的数据。要改必须先由管理员撤销奖项，规则是**公示即冻结**。

## 7. 三个练习（改完面试就有话说了）

1. **报名截止判断加时间**：现在只比较日期，改成比较到分钟（`sign_end` 存 `YYYY-MM-DD HH:MM`）。
2. **列表加「每页条数」选择**：把 `size` 固定值 8 改成从请求参数读，注意限制上限。
3. **加「撤销报名」**：学生可以取消待审核的报名。注意想清楚：是删记录还是改状态？会不会和唯一索引冲突？

每改完一个，记住「改之前什么现象、改之后什么现象」——面试问「你做过什么」时，这就是答案。

## 8. 常见报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: No module named 'flask'` | 没装 Flask | `pip install flask` |
| `OSError: [WinError 10048]` | 5000 端口被占 | 改 `app.py` 最后一行 `port=5001` |
| 页面数据乱了 | 演示数据改坏了 | 删 `contest.db` 重启 |
| 页面 500 | 代码有错 | 看命令行最后一段 Traceback |

`pip install` 慢的话换国内源：

```powershell
pip install flask -i https://pypi.tuna.tsinghua.edu.cn/simple
```
